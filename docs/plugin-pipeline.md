# 联机插件处理管线规范

> 本文是生命周期与分类的概念简表。实际新增插件时只需优先完整阅读 `docs/plugin-authoring-guide.md`，其中包含当前代码接线、平台作品模型调用、设置、卡片、成本和测试规范，不必再重复全文读取本文。

## 分类

插件按“作用位置”和“是否阻塞正式回合”分类：

1. **输入转换器（Input Transformer）**：在全员输入收齐后、正式作品收到输入前运行。所有已启用输入转换器都必须结束后才允许发送；每个插件接收当前输入集合并返回新的输入集合。
2. **输出转换器（Output Transformer）**：在房主模型完整输出后、下一轮输入开放前运行。所有已启用输出转换器都必须结束后才允许进入同步和下一轮。
3. **辅助处理器（Auxiliary Processor）**：不属于固定对话阻塞链，可由用户操作、作品选择、输入特征或其他事件触发。联机前置词适配属于此类。

“对话信息处理”是输入转换器和输出转换器在 UI 中的上层分组；“其他信息处理”对应辅助处理器。这样既保留用户理解上的两种模式，也让执行契约足够明确。

## 生命周期

```text
collecting
  → processing-input
  → generating
  → processing-output
  → syncing
  → collecting（下一轮）
```

- 输入插件按 `order`、再按插件 ID 确定性排序，依次接收上一插件返回的内容。
- 输出插件使用同样的顺序规则。
- 每次执行产生稳定 `runId`、插件 ID、阶段、回合号、开始/结束时间、状态和可选积分信息。
- 房主是唯一执行者；插件结果随权威 `round-input` / `round-result` 同步给访客，访客不再次调用插件作品或消耗积分。
- 输入转换器的可视结果不写入平台消息正文。工具按 `order` 把 Shadow DOM 卡片插入对应的真实用户输入行之后、模型输出之前；访客使用房主同步的同一份运行结果建立相同卡片。

## 失败策略

“独立视角”采用隐私例外：从 0.10.5 起，请求超时、报错或解析失败会重新加载后台整理作品，以空白新会话重发相同请求，最多尝试 3 次（含首次），成功即停；三次均失败时栈记录错误并完成回合，同步层只发送失败提示，不把原文当作公共内容。重试期间不提前同步；积分累计已读取的消耗。原文保留在房主平台会话中。其协议、前置词及提示词见 `docs/perspective-split-work-prompt.md`。

对话处理栈采用 **等待完成、失败开放（fail-open）**：

- 工具始终等待每个已启用插件返回、超时或报错。
- 单个插件失败后记录 `error` 结果并继续执行后续插件。
- 输入插件失败时沿用该插件收到的输入；输出插件失败时沿用该插件收到的输出。
- 即使所有插件失败，正式回合仍会发送，不因插件错误丢失玩家输入。

## 数据修改边界

当前效果判定只追加每位玩家命中的判定结果。规范允许后续插件声明并实现这些能力：

- 追加、前置或替换某位/全部玩家输入；
- 追加、前置或替换模型输出；
- 修改当前会话的提示词、前置词或后置词；
- 读取历史消息、成员资料、作品配置或用户输入；
- 产生只展示、不写入正式模型上下文的卡片；
- 产生要写入房主聚合输入的结构化结果。

实现新插件时应明确其阶段、顺序、输入契约、返回契约、积分来源、超时、失败回退和同步可见范围，不能绕开现有房主权威发送与访客编辑式同步链路。

## 效果判定插件

- 阶段：输入转换器。
- 平台作品：`/zh/explore/installed/8769d311-9a37-48e0-9b19-caf7590c6f15`，域名使用当前登录节点。
- 输入：控制参数与全部成员本轮原始输入位于 `request_json`；最近 `n` 条房主作品输出按从旧到新排列在独立的动态 Markdown 代码围栏中，并明确标为只读故事资料。围栏长度会避开历史正文已有的反引号序列。
- 模型输出：每名玩家只返回恰好 `x` 个不同程度及其后果，严格按“大成功 → … → 大失败”排列；请求不会把骰子面值 `y` 告诉模型。
- 参数约束：`y` 为 `6～20` 的整数；`x` 为 `4～y-2` 的整数，并必须包含“大成功、成功、失败、大失败”。
- 默认骰子为 `D10`；最近输出数量、程度数量、骰面和风格配置按账号配置持久化，重启后恢复最后一次保存值。
- 无历史输出的新会话允许预先勾选插件，但首轮跳过插件作品调用且不消耗额外积分；读到第一条模型输出后自动在后续回合生效。
- 本地处理：最低约 `10%` 骰面固定映射“大失败”，最高约 `10%` 固定映射“大成功”；中间程度按连续区间分配，越靠中间权重越大、越靠两端权重越小。房主再使用无偏整数随机数为每名玩家独立投掷一次。
- 正式作品输入：每名玩家的原始输入后只追加命中骰面的 `degree + outcome`，不追加点数或其他骰面。
- UI：插件设置页只负责配置。运行后在本轮用户输入正下方显示对话卡片，突出命中点数和结果，并可展开全部骰面结果；右下角显示平台实际返回的本次积分消耗。
