# 编辑器纯提示词《猎艳疆土》等价验收

核验日期：2026-10-02

## 结论

原有自主 Harness 只验收 `standalone/1` 单人游戏，能够生成界面、状态机、本地存档和受控模型任务，但不具备《猎艳疆土》的专用联机服务器、签名公共账本、地图并发合并、加密书信、服主管理和服务器迁移能力。因此，单靠模型重新编写一个相似页面，不能视为“功能与猎艳疆土一致”。

当前新增一条确定性创建路径：当空白项目的纯提示词明确要求“创建/生成/复刻一个功能与猎艳疆土完整一致的新游戏”时，编辑器直接从当前客户端内置、已回归的《猎艳疆土》模板实例化新草稿。新草稿使用新的卡片身份和待创建伴生作品，但复用同一版本的规则引擎、宿主服务、签名协议、模型任务配置和完整前端程序。这样“功能一致”由代码来源和自动验证保证，而不是由模型自述或视觉相似度判断。

## “创建成功”的机器判定

`electron/editor-grid-parity.cjs` 的 `gridParityCapabilityReport()` 将创建成功定义为下列十一组检查全部通过：

1. **identity**：项目仍是当前账号与节点下的新建本地草稿，使用独立 `draftId/cardId`，且尚未绑定 `workId`。
2. **program**：`gameId`、完整 HTML、`fyow-grid-conquest` source、`fyow-host/1` 和程序摘要有效。
3. **configuration**：前置词、主提示词、后置词和全部世界书与当前内置模板一致。
4. **model-tasks**：七项结构化模型任务全部存在。
5. **rules**：64×64 地图、确定性地块、时间结算、战报、将领市场和宝物规则存在。
6. **intents**：29 项玩家意图在权威规则引擎中存在。
7. **service**：初始化、行动、聊天、私信、管理、快照、同步、迁移和模型服务存在。
8. **protocol**：13 类签名记录 Schema 与分片编码存在。
9. **communication**：世界聊天、加密书信、签名账本、重连和迁移存在。
10. **administration**：八项服主操作存在。
11. **interface**：地图、通讯、将领、市场、战报、管理和积分展示入口存在。

任一程序字符被替换，或任何任务、规则、协议、服务、管理命令和关键界面标记缺失，`assertGridParityProject()` 都会拒绝把项目标记为等价创建成功。

## 创建和发布语义

- 纯提示词只负责表达创建意图和可选的新游戏名称。
- 草稿保留当前账号、节点、项目 ID、编辑历史和发布状态。
- 草稿的 `workId` 为空，避免错误绑定官方《猎艳疆土》作品。
- 保存并同步时创建新的伴生作品；发布卡继续使用 `cc.aiero.fyow.grid-conquest` 专用运行时，因此获得完整宿主能力。
- 模板实例化不调用开发模型，不消耗开发积分；游戏运行中的结构化人物内容仍按实际模型调用返回输入、输出、总消耗和剩余积分。
- 普通单人游戏和非等价需求仍走自主 Harness，不会被自动转换为疆土服务器。

## 自动验证

新增命令：

```powershell
npm run verify:editor-parity
```

它先从一条纯提示词创建草稿，验证十组能力、执行权威加入规则烟雾测试、重新组包并通过游戏卡校验；随后运行：

- `tests/editor-grid-parity.test.ts`
- `tests/grid-world-game.test.ts`
- `tests/online-world-protocol.test.ts`
- `tests/online-world-card.test.ts`
- `tests/online-world-service.test.ts`
- `tests/online-world-migration-regression.test.ts`

截至 2026-10-02，该专项命令覆盖 257 项测试并全部通过。
