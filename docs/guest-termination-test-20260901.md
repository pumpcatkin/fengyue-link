# 0.10.7 访客终止与同步实测

测试日期：2026-09-01（北京时间）。使用用户授权的八爪毛米账号，在 staging.aiero.cc 的隔离测试会话中测试。没有修改已有剧情记录或平台作品提示词；测试期间临时切换的作品默认模型已恢复。测试账号密码未写入源代码、报告或安装包。

## 发现与修复

旧版本在任务编号尚未返回时点击平台停止按钮。该按钮会立即恢复空闲界面，但没有任务编号就无法向服务端发送停止请求。原日志中已报告停止，编辑框内容却仍持续增长，覆盖房主正文。

新版直接观察访客原生请求的流式响应，取得真实 `task_id` 就调用平台停止接口。只有服务端停止确认且响应流结束，或明确自然完成，才能继续编辑。停止接口失败可重试，但本轮生成请求不会重复发送；连接断开、按钮消失都不能冒充停止成功。

同步时使用这次请求返回的消息 ID 核对平台记录，先重载对应会话以清除排队中的前端流更新，再打开原生编辑框保存房主正文。另修复 textarea 自动把 CRLF/CR 转为 LF 导致的“未完整写入”误报。结果未验证之前，访客仍看不到临时生成内容。

## 多系列比较

实时模型列表共 110 项，选择六个不同系列的可用型号。开始尝试六路并行，并降低到两路并行，发现两个平台限制：

- 同账号并发会返回“系统繁忙”，未生成任务编号的拒绝请求不计为停止失败。
- 保存每个测试会话的模型后，实际请求仍使用作品的全局模型。已通过 SSE 的实际型号确认，因此这些并行样本不能用来比较不同系列。

有效比较改为受控切换作品默认模型，每个型号三次。每次检查 SSE 返回的实际型号，收到任务编号立即停止，读到流结束，再三次读取服务端消息记录，确认没有继续增长。下表只包含实际型号匹配的 18 次有效样本。耗时为请求发出到响应流结束，包含平台及网络耗时。

| 系列 | 平台实际型号 | 停止并保持正文为空 | 耗时中位数 | 耗时范围 | 单次记录积分 |
| --- | --- | ---: | ---: | ---: | ---: |
| Grok | `sticky_grok / grok-4.5` | 3/3 | 427 ms | 423–608 ms | 2 |
| GLM（Other） | `dian_glm / glm-5.3-flash` | 3/3 | 482 ms | 434–561 ms | 2 |
| Gemini | `yuegle_google_vertex / gemini-2.5-flash` | 3/3 | 540 ms | 465–720 ms | 2 |
| GPT | `dian_openai_codex / gpt-5.4` | 3/3 | 610 ms | 567–1501 ms | 2 |
| DeepSeek | `hiagi_deepseek / deepseek-v4-flash` | 3/3 | 631 ms | 562–646 ms | 2 |
| Claude | `manei_anthropic_official_v2 / claude-sonnet-4-6` | 3/3 | 697 ms | 508–765 ms | 2 |

六组均为零正文字符、平台报告零 token，三次后续读取均未增长。Grok 在本轮样本中结束最快，因此作为访客首选。每组仅三个样本，不能证明 Grok 长期比其他系列更可靠；本轮停止成功率相同，核心修复是正确取得任务编号并调用停止接口。

**停止成功仍可能扣积分。** 18 个有效样本均报告输入 1 积分、输出 1 积分，共 2 积分。这不是根据 token 估算，不能据此承诺任何作品、账号或未来平台规则下的固定收费，更不能保证零积分。上述 18 个有效比较样本合计 36 积分，不含前期探查和完整流程回归请求。

## 应用策略与验证范围

访客加入房间、切换锚定会话和每轮首次发送前，刷新模型列表并优先选取实际存在的 `sticky_grok / grok-4.5`。精确型号缺失时查找可用 Grok；同系列候选按价格、同价出字率排序。整个系列缺失时仅回退到列表中存在的其他已测精确型号；没有候选则停止占位发送。作品默认与会话模型均写入并回读确认，房主模型及提示词不受修改。

最终代码通过原生 Electron 访客流程连续两轮回归：真实发送、服务端确认停止、正文零字符，然后保存 2927 字符的合成 HTML 房主结果并通过平台读回校验（编辑框换行转换后为 2925 字符）。这项回归覆盖访客平台链路；没有把它当作两个真实账号完整联机网络传输的端到端测试。包传输、显示门控、失败保持隐藏等行为由本地回归覆盖。

本地 142 项测试通过，构建和语法检查通过，依赖审计无已知漏洞。安装包另外执行离线 Electron 页面与原生浮层回归，检查“当前对话已适配”等文案，并核对包内代码与工作区代码一致。
