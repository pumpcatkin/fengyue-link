当前主要测试载体是 Electron 桌面版：“本地工具界面 + 隐藏浏览器后端”，不把工具覆盖到风月页面上，也不要求安装浏览器扩展。它不部署私人服务器，不导出 Cookie，不绕过登录；所有跨设备数据都通过风月 `/zh/chats` 私信传输。登录状态保存在正式应用内每个账号实例自己的持久化分区中。

桌面版的平台可见性规则：登录阶段只显示工具自己的登录面板，账号密码由隐藏浏览器提交；房主选择作品时临时显示探索页；选中作品的跳转会被主进程拦截并立即隐藏。介绍阶段仅放行作品的非广告 iframe，游玩阶段仅放行 `.chat-container`，私信协议由隐藏的账号会话通过平台接口处理。

每个账号实例始终保留一个不可见的 `/zh/chats` 常驻页面，并以同一持久化分区向作品页同步 Cookie、缓存和本地存储。登录前工具会解析 `https://aify.pages.dev/` 的 `SITES` 列表，但只接受程序内审核过的 HTTPS 节点，再逐项检测 `/zh/chats`；登录成功后，本次进程内的域名会锁定。工具可选择使用 Electron `safeStorage`（Windows DPAPI）加密保存账号密码；凭据按实例隔离，不以明文写入项目文件。

默认会话和每个账号持久化分区都会显式使用 Windows 系统代理设置；作品选择页不施加工具侧网络超时。登录后的临时令牌不可读或网络失败不会让界面退回登录页，只有平台账号接口持续明确拒绝认证时才确认会话失效。

房间协议复用账号常驻会话的私信 API，不再为每个私信频道创建和轮询额外 BrowserWindow。点击“实例 → 打开独立账号实例”可启动另一个 `persist:fengyue-link-{profile}` 会话，在同一台电脑上同时登录多个不同账号。

“日志”和“实例”属于管理员调试功能。工具以平台账号资料接口返回的邮箱为准，仅 `8zhua@test.com` 会在界面中看到这两个入口；主进程也会拒绝普通账号读取日志或启动隔离实例。诊断日志会隐藏凭据、令牌、角色私密设定和对话正文，正常关闭时删除当前文件；异常退出遗留文件会按 7 天、20 个文件和 20 MiB 三重上限自动清理。

## 为什么不是独立 HTML

独立 HTML/PWA 与风月属于不同源，浏览器会阻止它读取登录态、操作作品输入框和编辑 `chat-container`。用户脚本注入后与页面同源运行，仍然使用 HTML/CSS/TypeScript 写界面，同时能在桌面浏览器和安卓的 Tampermonkey/Violentmonkey 环境运行。

## 桌面版私人邀请链路

房主先选择实际游玩的作品，再点击“创建房间”。工具会在隐藏账号会话中调用平台的简易创作（`type: 2`）生成一个私人作品，并只显示 `/zh/explore/installed/{id}` 邀请后缀；不会使用高级创作，也不会进入公开聊天室。

成员点击“加入房间”，只需粘贴该后缀并输入房间密码。工具会拼接成员登录时选定的域名，从作品详情识别作者账号 ID 和用户名，自动创建或复用与房主的私人聊天，再执行 `hello → challenge → join-proof → join-accept` 认证。双方不需要提前存在私聊。旧版完整链接仍可输入，但只使用其中的通用后缀。加入失败或超时后可以退出当前房间并立即重试。

加入过程不需要房主手动批准：成员点击“直接加入房间”后，房主端会在后台自动验证邀请后缀和密码，正确时直接接纳。工具登录后还会读取平台个人资料中的当前等级；低于 2 级的账号不能创建或加入联机房间。房间存在期间，房主和成员端都会禁用“选择作品”，退出或关闭房间后自动恢复。

房间内置独立的实时聊天页。访客消息只通过与房主的私聊发送给房主，不会直接联系其他成员。每位成员点击发送时，工具会固定生成 Unix 毫秒时间戳及对应的 ISO 8601 时间并一同发给房主；房主按成员的真实发送时间排序，然后只向所有访客广播这一条新增消息，不需要等待房主本人发言。两条消息处于同一毫秒时使用稳定消息 ID 作确定性兜底，不使用成员自行生成的编号决定显示顺序。协议修订号只用于检测漏包；新成员首次加入或客户端检测到修订号断档时，才向房主请求压缩的完整聊天快照。发送、广播和断档恢复都带自动重试，因此正常聊天不会反复传输整份历史，网络波动后仍可恢复到同一顺序和内容。

桌面版会为同一作品预先维护两个相互独立但共享账号登录态的页面：介绍页面会锁定作品提供的 `iframe[sandbox*="allow-pointer-lock"]`，游玩页面则一直在后台等待 `.chat-container` 出现。两个页面互不替换，因此开始对话后仍可返回原介绍视窗。

选择作品后，工具会读取平台的完整会话列表（例如“新的对话-1”），可在侧边栏切换已有会话或新建会话。选择与新建通过平台使用的 `conversationIdInfo` 状态完成，不再依赖隐藏页面里的“新对话”按钮。房间会绑定一个不可见的稳定会话键：房主的平台会话 UUID 与每位访客各自的平台会话 UUID 分别写入 Electron `userData/save-anchors/{实例}.json`，不依赖浏览器缓存，也不使用可修改的会话名称。访客首次加入该房主会话时只建立空白对应会话，不回填历史；以后再次加入同一房主会话时自动打开上次锚定的访客会话，只继续同步新回合。

回合链路已经接线：成员确认输入后通过私聊发送给房主；房主按成员设定名生成不含账号 ID 的 JSON 输入，只在房主作品页调用模型；输出结束后读取原始回复、模型、输入积分、输出积分与总积分，并以压缩分片私聊广播。接收端会等待全部分片到齐后再解压，避免长回复在第一片到达时被误判并丢弃。成员端收到结果后执行“写入聚合输入 → 立即停止 → 编辑空 AI 回复”，把房主结果保存进自己的平台对话记录；工具里的该视图统一命名为“对话界面”。

房主的对话界面直接挂载后台作品页的实时 WebContents 画面，不经过截图轮询；发送后会持续监听新增与流式更新的消息节点，只显示 `.relative.flex.items-start.justify-between.gap-3.py-3.px-3` 元素及其所有子元素。访客在房主生成期间只看到等待提示，收到完整结果后才在隐藏页面执行记录同步；失败会保留步骤状态并最多自动重试 4 次。

## 开发与安装

制作新的联机工具内插件时，先阅读 [`docs/plugin-authoring-guide.md`](docs/plugin-authoring-guide.md)。它覆盖平台作品模型调用、插件阶段、设置持久化、房主权威同步、对话卡片、积分控制和测试清单；插件专项任务不必重复加载完整项目交接文档。

```powershell
npm install
npm test
npm run build
npm run desktop
npm run pack:win
```

正式 GitHub Release 还需使用项目目录外的 Ed25519 私钥生成签名发布清单；完整步骤见 [`docs/release-security.md`](docs/release-security.md)。

`npm run build` 会生成浏览器脚本 `dist/fengyue-link.user.js`；`npm run pack:win` 会在 `release` 目录生成包含 Electron 与 Node.js 运行时的 Windows x64 NSIS 安装包，以及自动更新所需的 `latest.yml` 和 blockmap。普通用户只运行安装包，不需要安装 Node.js；只有源码开发与本地打包需要 Node.js/npm。

正式安装包使用固定应用 ID 与安装器 GUID，可直接覆盖后续正式版本并保留正式用户数据。发布更新时仍需先提升 `package.json` 版本并生成新安装包。

域名目录以后若新增域名，需要把新域名加入 `vite.config.ts` 的 `@match` 后重新构建；这样可以避免脚本在无关网站上运行。

## 协议路线

1. 成员发送 `hello`。
2. 房主回 `challenge`，双方均为镜像时使用 scrypt-v2 慢速派生值生成 `join-proof`；任一方为原版时自动兼容 sha256-v1。
3. 房主验证后回 `join-accept` 并广播成员名单，同时下发作品后缀和房主会话键。
4. 新访客按房主的稳定会话键建立空白平台会话并发送 `anchor-ready`；已锚定访客直接恢复自己的对应平台会话。加入时不复制房主历史，也不按可修改的会话名称匹配。
5. 每轮成员发送 `turn-submit`，房主广播 `turn-state`。
6. 房主聚合输入并只在房主作品页生成；完成后广播 `round-result`，其中包含聚合输入、输出、模型、输入/输出/总积分消耗和时间戳。

认证、回合准备、作品输入接管、生成完成检测、积分/模型抓取和成员端原生记录回填均已接线。

## 多人会话提示词

房主首轮真正调用模型前，工具会把通用多人前置词和全体玩家的人设写入当前作品的当前会话配置。受控区块始终位于对应字段最后方，已有区块会被替换而不会重复追加，标签外的原有提示词会完整保留。对于尚无平台 UUID 的全新会话，工具先通过平台原生的发送后立即终止流程建立 UUID，写入并验证会话配置后删除初始化记录；整个过程只使用 `is_global: false`，不会修改作品全局配置。详细字段、默认规则及专属作品适配建议见 [docs/multiplayer-prompt-injection.md](docs/multiplayer-prompt-injection.md)。

选择作品后还可使用“联机前置词适配”。工具读取该作品全部已有会话，各自只复制最后一段 AI 回复到固定的“多人联机状态栏适配器”作品中进行一次模型分析；该操作会消耗积分。验证后的专属片段按作品 UUID 永久保存在本地，并由工具固定追加到通用前置词。再次适配只在新结果有效后覆盖旧片段，生成失败不会破坏原锚点。
