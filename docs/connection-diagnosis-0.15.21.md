# 0.15.21 登录与连接稳定性诊断

日期：2026-09-21。测试均由主任务执行，未使用子智能体。

勘误（2026-09-22）：下文“全量只读读取”的 2 页结果后来证实受历史分页缺陷影响，并非整本云端账本。平台会在中间页返回不足 50 条根数据，原逻辑在该处提前停止。0.15.22 已修复并增加总页数及有效控制、状态记录断言，详见 `cloud-pagination-diagnosis-0.15.22.md`。

## 证据与原因

1. 真实平台登录页有服务端输出的输入框，但 Next.js/React 接管表单晚于 DOM 就绪。旧流程在 DOM 就绪后立即填入并点击，日志已写 submitted，实际却没有 `/console/api/login` 请求；稍后 React 将两个输入清空。隔离会话连续换节点仍重复此现象。等待输入框完成 React 绑定后，真实请求发出并完成认证。
2. 账号心跳失败时，旧流程重新加载共享后台账号页；普通平台 API 在该页的 executeJavaScript 中等待 fetch。导航可终止并发请求，错误恢复过程本身可能制造额外断连。
3. 评论根页有临时故障重试，但回复分片接口此前没有同等处理。当前运行日志实际包含 7 次回复分片 Failed to fetch、3 次回复分片超时和 4 次由分片读取中断触发的同步失败。
4. 资料接口的 HTTP 200 业务错误被判作未登录；在线游戏服务未包含在既有活动会话保护条件内。
5. 部分非 JSON 响应被转换为空对象，随后可能被读取链视为空列表。节点探测把 HTTP 403、429 等也列为在线，切换流程在一轮中继续使用旧探测列表。

## 修复

- 登录只选择可见、可编辑且属于同一表单的输入框；Next.js 页面等待 React 绑定，填入后核对内容仍在，再提交。平台声明支持用户名时修正 email 类型导致的浏览器表单校验阻断。
- 每次节点失败后重新采用后台更新的可达性排序，保留取消和持续换节点功能。密码错误、验证码和限流不触发反复提交凭据。
- 普通平台 API 改用当前账号的 Chromium session.fetch，继续使用 HttpOnly Cookie 和可选旧 bearer token，不随后台页面导航而中断。
- 心跳单飞、有限等待；最近已有成功平台请求时跳过额外心跳，失败后不刷新共享页面。
- 根页和回复分片均只对临时网络故障进行有限重试。通用网络层不自动重复写入，评论事务仍使用原记录标识与原有确认流程。
- HTTP 429 按 Retry-After 暂缓当前节点请求；401/403、业务失败、非 JSON 和错误列表结构分开报告。失败不降格为空数据，现有完整存档继续保留。
- 时间校准采用同一会话且设置有限等待，避免单次时间接口挂起长期占用同步流程。
- 平台资料业务错误视为暂时未知，在线游戏会话不因该探测结果被清空。
- 网络日志增加路径、错误码、HTTP 状态和耗时，不记录请求正文、密码、Cookie 或令牌。

## 验证

- Vitest：39 个文件、611 项测试全部通过。
- TypeScript 与 Vite 构建通过。
- 真实 Electron 本地故障测试：隐藏表单、600ms 延迟接管、持续挂起图片、用户名填入 email 控件、HttpOnly Cookie、关闭后台渲染页后的在途写入、取消登录全部通过。延迟场景约 871ms 登录，取消约 4ms；不是公网耗时承诺。
- 真实平台：两个官方域名发布页去重后 10 个节点，这轮登录页与未认证资料接口均成功。
- 隔离内存会话真实登录：aigirlfriend.baby 约 3.57s，acquant.xyz 约 3.98s。两个登录均真实收到 `/console/api/login` HTTP 200，并核对账号资料。
- 每次登录后连续三轮账号、游戏数据根页和回复读取成功。
- 全量只读读取当前伴生作品：2 页、351 条根及回复数据、97 条完整协议记录、0 条无效记录；发现 2 条 MAP 缺分片记录（2 段中仅 1 段、7 段中仅 5 段）。本轮所有回复读取成功，故不能把它们表述为完整同步；保留既有不应用半条记录、覆盖水位不越过缺片根记录的规则。未删除或改写这些云端记录。
- 桌面离线集成与生产预加载沙箱验证通过。

## 交付范围

本轮修改客户端网络和登录层，不改游戏规则、平台介绍、游戏卡 JSON、现有存档或桌面快捷方式。新行为需要运行 0.15.21 客户端；当前已启动的旧程序不会因源码修改自动改变。真实平台测试不提交游戏行动或模型生成，不消耗模型积分。

测试者所在网络的 DNS、代理、线路和平台端故障仍可能造成请求失败。后续出现问题可用 Ctrl+Shift+8 导出对应时间段日志，以区分平台 HTTP 状态、连接故障和数据分片缺失。
