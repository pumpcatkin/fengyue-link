# 0.11.4 既有插件与刷新链审计

审计日期：2026-09-03。范围包含两个正式对话插件“效果判定”“独立视角”，以及辅助处理器“联机前置词适配”。本次没有调用付费平台模型，也没有修改用户的平台作品、会话或插件配置；验证使用源码检查、保存配置样本、单元/回归测试及离线 Electron 验证。

## 结论

| 功能 | 结论 | 本次处理 |
| --- | --- | --- |
| 效果判定 | 输入阶段、设置归一化、模型协议解析、骰面映射、失败开放和卡片同步逻辑一致，未发现新的确定性功能错误 | 增加刷新回归覆盖，确保刷新上一条回复时保留本回合已有的输入插件运行记录 |
| 独立视角 | 正常回合仍遵守三次重试、逐访客输出和失败不公开原文；发现刷新路径绕过通用输出栈并覆盖全部 `pluginRuns`，且刷新失败后可能遗留页面展示锁 | 刷新/编辑统一重新执行输出插件栈，只替换旧输出阶段记录；曾经拆分过的结果刷新时继续强制独立视角；成功、失败或退出房间都会解除临时展示锁 |
| 联机前置词适配 | v2 片段解析、受管标记替换、作品/会话配置边界及测试通过，未发现新的确定性功能错误 | 修正文档中“输出转换器暂无”和只支持一个插件的过时说明，不改适配协议与平台写入方案 |
| 回复刷新基础链 | 确认按钮仍使用网页 `window.confirm`，与原生作品视图的层级冲突，点击后可能看似无反应；操作按钮只在回复节点内查找也过窄 | 统一改用窗口级确认框；从回复节点和消息行双路径查找刷新、编辑、删除按钮；积分选择优先限定在可见弹层内 |
| 房间轮询 | 实际日志出现退出房间后继续读取 `this.room.role` 的空引用 | 轮询绑定启动时房间快照；任何异步等待后发现房间已退出或切换便停止旧轮询 |

## 保持不变的边界

- 房主仍是唯一插件执行者；访客只接收房主权威结果，不重复调用插件作品。
- 效果判定仍在正式作品生成前运行，独立视角仍在正式输出后运行。
- 单个插件报错仍记录错误并继续流程；独立视角继续采用隐私例外，失败时只发占位提示。
- 刷新只由房主平台模型重新生成；访客使用编辑方式写入房主同步结果，不在访客端再次消耗刷新积分。
- 联机协议类型、插件设置 schema、作品 appId、提示词协议及正式用户数据目录均未改变。
