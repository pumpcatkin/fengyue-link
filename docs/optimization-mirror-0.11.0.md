## 已实施优化

1. 本地窗口启用 Chromium sandbox 和严格 CSP；禁止新窗口和非本地导航。所有 IPC 统一验证调用者必须是主工具页或设置页。
2. 删除无调用的 `fy:fetch-text`、旧桌面私信通道 IPC、私信 BrowserWindow 轮询，以及 28,782 字符的 `syncGuestRoundResultLegacy` 旧实现。
3. 域名目录只允许内置审核列表中的 HTTPS origin，拒绝 HTTP、陌生域名和重定向到陌生域名的节点。
4. 镜像互联自动使用 scrypt-v2 房间密码派生；与原版互联自动回退 sha256-v1。新房间密码至少 8 位、最多 128 位。
5. `hello` 中的账号 ID 必须与平台私聊对端 ID 一致；证明阶段不得替换角色资料。所有认证后上行消息必须来自该成员绑定的私聊 ID。
6. 大包发送前限制未压缩数据为 8 MiB、压缩分片最多 256 个；接收端限制分片字段、编码体积、解压输出及同时传输数。
7. 已处理数据包缓存最多 10,000 项，房间聊天保留最近 1,000 条，待广播队列最多 200 条。
8. 空闲协议轮询逐步退避到约 3 秒；检测到消息后恢复每秒检查。
9. 配置写入改为临时文件原子替换，并保留 `.bak`；读取损坏 JSON 时尝试上一份备份。
10. 日志隐藏凭据、令牌、对话正文和角色私密字段；内存最多 2,000 条、单条最多 64 KiB，异常退出文件按 7 天、20 个或 20 MiB 清理。
11. 登录、角色、房间、聊天和回合输入增加长度及数量限制，防止意外粘贴或恶意输入耗尽内存。

离线验收除常规桌面集成脚本外，还应运行 `npm run verify:sandbox`，确认正式 preload 在 `sandbox: true` 和 CSP 环境中可以完成版本与初始状态渲染。

## 保留的谨慎边界

- 未改变作品调用、访客记录回填、独立视角和插件执行顺序。
- 未强制采用不兼容的新协议；旧客户端互联仍可用，但旧客户端参与时密码证明会回退到旧算法。
- 未进行真实账号登录、真实私信发送、作品写入或积分消耗测试；这些必须使用专门测试账号人工验收。
- `electron/main.cjs` 仍然较大。本次只抽出无 Electron 依赖的运行时工具；继续拆分平台自动化模块应按功能逐块进行，并为真实 DOM/API 行为建立夹具后再做。
