# 游戏卡接口规范化与创作助手方案

日期：2026-09-23  
状态：设计稿，尚未实现 `/2` 协议。本文不修改当前游戏程序、平台作品、客户端版本或测试进程。

## 1. 目标与边界

产品目标是让玩家通过联机工具内的创作助手，调用风月模型生成、编辑和测试游戏卡，包括主要程序、提示词和世界书；新游戏应复用工具能力，而不是每做一张卡就添加一套客户端业务接口。

按本次需求确定信息边界：

| 内容 | 游戏卡可用性 | 规则 |
| --- | --- | --- |
| 风月账号 ID、公开昵称 | 允许 | 宿主生成专用账号视图，昵称中含邮箱时使用中性别名 |
| 本游戏资源、进度、设定、角色记忆、互动记录 | 允许 | 限定当前游戏与当前局；这些内容的可用性不等于开放其他游戏或整个平台账号的资料 |
| 本游戏公开地图、交易、玩家记录 | 允许 | 经本游戏的数据接口读取 |
| 平台积分余额和模型消耗 | 可声明使用 | 与游戏金币区分；允许展示余额不等于允许无限调用计费模型 |
| 邮箱、登录密码、验证码、Token、Cookie、登录态、签名私钥 | 宿主私有 | 不进入卡片状态、模型上下文、普通回包、共享记录或导出卡包 |
| 电话、真实住址等平台个人资料 | 默认宿主私有 | 不读取无关资料，不将平台原始个人资料对象交给卡片 |
| 本机路径、系统用户名、剪贴板、任意文件、其他作品的私信 | 不属于游戏 API | 通过受信宿主的独立功能处理，不由卡片自行读取 |

不以防作弊为本期目标。允许卡片自由实现游戏内规则、修改其自身游戏状态；保留身份绑定和账号隔离，是为了保护账号能力与防止跨游戏误操作，不是为了宣称游戏数值绝对可信。

防护承诺针对工具掌握的资料及能力。玩家自行在卡片输入框里写入现实信息、使用含邮箱的公开昵称、主动发送个人资料，另有信息暴露风险；沙箱和字段白名单不等于任意文字的自动隐私识别器。登录入口、权限确认和积分确认须保留在卡片区域之外的受信工具界面。

### 2.2 需要补验的宿主边界

[preload.cjs](D:/风月联机工具/electron/preload.cjs:1) 暴露桌面功能，缺少显式主框架限定；[main.cjs](D:/风月联机工具/electron/main.cjs:9714) 的 IPC 检查使用已知 `webContents` 及其顶层 URL，未同时限定 `event.senderFrame`。

这两点应当加固并用真实 Electron 子框架测试验证；当前检查尚未证明游戏 iframe 实际拥有桌面预加载 API，不将潜在风险表述为已复现的凭据读取漏洞。

## 3. 架构选择

```text
受信工具界面
  登录 / 创作编辑器 / 权限确认 / 积分确认 / 发布确认
                         |
                   主进程能力代理
  账号投影 / 分区存档 / 云端队列 / 模型调用 / 作品配置适配器
                         |
              校验并绑定会话的 fyow-host/2
                         |
                 不受信游戏运行环境
             界面、玩法、数值、交互、计时表现
```

分成三个层次：

1. **程序自由，外部能力固定。** 卡片可编写自己的 JavaScript 玩法，不获得任意 HTTP、文件、Shell、登录或桌面 IPC 能力。
2. **游戏规则不再硬编码到工具。** 新卡自行计算游戏结果，通过通用存档、数据和模型接口提交。宿主校验结构、作用域、调用配额和数据生命周期，不替所有游戏编写战斗引擎。
3. **猎艳疆土保留兼容适配器。** 原有受信游戏引擎继续运行；新卡不通过伪造 `fyow-grid-conquest` 标记接入其特殊权限。

建议第三方卡使用独立、临时会话分区的沙箱 `WebContents`，与登录分区、桌面页面分离。卡片预加载仅提供卡片 SDK，或由专用壳通过消息端口注入 SDK；不加载桌面的 `fengyueBackend`。主进程对卡片分区实施网络、导航、新窗口、下载、设备权限等限制，并通过运行测试验证，不能只凭 CSP 文本推断全部网络途径已封闭。

自定义代码始终在不受信环境执行。构建、存档迁移、模型解析和云端回放均不把作者提供的 JS 放进主进程 `eval`；也不把 Node.js 的普通上下文当作恶意代码隔离边界。

## 4. 卡包与版本

新提议：

- 导入/导出包：`fyow.game-card/2`。
- 作品详细介绍中的可执行发布包：`fyow.program/2`。
- 卡片与工具通讯：`fyow-host/2`。
- 数据、模型任务、存档各有独立 `schemaVersion`。
- 卡片内容版本和最低客户端版本独立；仅改玩法或提示词通常不需要升级客户端。

示意 manifest，键名为拟议协议，不是现有导入格式：

```json
{
  "schema": "fyow.game-card/2",
  "gameId": "community.example.strategy",
  "cardVersion": "1.0.0",
  "hostApi": 2,
  "runtime": {
    "engine": "sandbox-game",
    "entry": "program.html"
  },
  "binding": {
    "bootstrapWorkId": "BOUND_WORK_ID",
    "authorAccountId": "AUTHOR_ACCOUNT_ID"
  },
  "permissions": [
    "identity.read",
    "save.read",
    "save.commit",
    "records.read",
    "records.write",
    "records.retire",
    "model.request"
  ],
  "definitions": {
    "saveSchema": "schemas/save-v1.json",
    "recordTypes": "schemas/records-v1.json",
    "modelTasks": "prompts/tasks-v1.json"
  }
}
```

包中逻辑路径只用于解析包内条目，不映射成可由卡片指定的磁盘路径。路径须规范化，拒绝绝对路径、上级目录、重复条目和外部引用；限制各条目及总解压大小。宿主根据当前安装记录确定实际游戏、作者和作品，忽略请求体对这些身份的改写。

摘要用于发现内容损坏；自报摘要不代表作者可信或代码安全。发布身份依据平台回读的作品作者，以及已有受信路由链；作品 URL 和作者 ID 不由卡片在运行中随意切换。

## 5. 通用 API

以下为 SDK 的建议接口，全部由宿主校验，卡片不持有平台地址或访问令牌。

| API | 用途 | 硬性边界 |
| --- | --- | --- |
| `identity.get()` | 获取账号 ID、清理后的昵称 | 仅返回专用视图，排除原始账号对象 |
| `context.get()` | 当前游戏、当前局、运行会话、宿主能力 | 工作与局身份由宿主注入 |
| `clock.get()` | 联网校准时间及校准状态 | 不把本机时间伪装为已校准平台时间 |
| `save.read()` | 读取当前玩家本局存档和 revision | 无磁盘路径参数 |
| `save.commit()` | 以预期 revision 原子保存本局数据 | 冲突显式返回，不静默覆盖 |
| `records.query()` | 读取声明的数据类型 | 仅当前绑定作品与局；返回规范化数据，不返回平台原始作者资料 |
| `records.write()` | 发布已声明类型的记录 | 宿主补齐作者、游戏、局、幂等标识并签名 |
| `records.retire()` | 退役自身已失效的记录 | 按生命周期证明删除，而非任意平台评论 ID 删除 |
| `operations.commit()` | 原子持久化存档变化和云端待办 | 仅承诺本机原子入队，远端结果另行确认 |
| `operations.get()/subscribe()` | 获取操作状态 | 区分已落盘、待同步、已确认、冲突和阻塞 |
| `sync.request()/subscribe()` | 请求同步和接收数据变更 | 合并重复请求；完整性状态由宿主报告 |
| `model.run()` | 调用声明的模型任务 | 固定绑定作品、输入/输出 Schema、计费许可 |
| `messages.send()/list()` | 游戏内定向书信，可选权限 | 只处理本游戏封装消息，不开放整个平台私信收件箱 |
| `ui.notify()/confirm()` | 提示、普通确认 | 固定文本/按钮参数，不渲染作者 HTML |
| `audio.play()/setVolume()` | 音效 | 包内资源与宿主音量范围 |
| `library.close()` | 返回游戏库 | 无桌面应用管理权限 |

主进程统一规则：

- 未声明的 API、记录类型、模型任务拒绝执行。
- 不设置 `fetch(url)`、`requestConsole(path)`、`readFile(path)`、`getRawProfile()`、`executeJavaScript()` 等通用穿透入口。
- 记录 ID 是宿主返回的句柄，不是全平台评论编号；传入其他卡片的句柄不会扩大作用域。
- 创建作品、更新配置、搬迁、账号操作属于工具管理功能，不属于普通卡片 SDK。
- 配额取“客户端硬上限、用户授权、本卡声明”三者中的最小值，卡片升级无权自行扩大许可。
- 游戏内作弊的容忍不扩展至对平台刷请求、消耗无限积分或跨账号操作。

## 6. 消息与会话规范

```json
{
  "protocol": "fyow-host/2",
  "kind": "request",
  "sessionId": "HOST_ISSUED_SESSION",
  "requestId": "REQUEST_UUID",
  "method": "records.write",
  "params": {
    "type": "world.entity",
    "idempotencyKey": "BUSINESS_OPERATION_UUID",
    "payload": {
      "entityId": "entity-1",
      "value": 10
    }
  }
}
```

`requestId` 区分一次通讯；`idempotencyKey` 标识一次业务动作。重发保留业务标识，同标识而载荷不同返回冲突。

通过验证当前框架来源的一次握手建立专用消息端口。会话绑定实际发送框架、程序摘要、当前账号、作品及当前局；更换账号、迁移、退出卡片或重新加载程序即撤销旧端口。会话编号是关联标识，不是卡片拿到后就能调用桌面权限的万能密钥。

主进程仍验证真实 `webContents`、`senderFrame` 及其对应注册记录。请求体里的 `actorAccountId`、`isAuthor`、`workId`、`sessionId` 不能自行证明权限。

统一回包：

```json
{
  "protocol": "fyow-host/2",
  "kind": "result",
  "sessionId": "HOST_ISSUED_SESSION",
  "requestId": "REQUEST_UUID",
  "ok": true,
  "result": {
    "operationId": "OPERATION_UUID",
    "status": "queued"
  }
}
```

错误仅返回 `code`、通用 `message`、`retryable`、`retryAfterMs`、`operationId` 等白名单字段。排除原始响应体、请求头、完整 URL、堆栈、本机路径和账号资料。

建议错误分类：`SCHEMA_INVALID`、`PERMISSION_DENIED`、`SESSION_EXPIRED`、`STATE_CONFLICT`、`SYNC_INCOMPLETE`、`RATE_LIMITED`、`AUTH_REQUIRED`、`MODEL_RESULT_INVALID`、`BUDGET_CONFIRM_REQUIRED`。模型或卡片生成的错误文本不直接作为宿主错误展示。

## 7. 存档、上传清单和删除

所有存档、记录句柄、消息与队列项绑定：

```text
gameId + serverInstanceId + seasonId + accountId
```

`serverInstanceId` 是逻辑服务器身份，绑定当前作品路由；保留进度的搬迁可续用，重开新局须更换 `seasonId`。是否保留进度由受信搬迁流程明确选择，队列不根据“当前作品”自动改投。

### 7.1 本地动作

纯本地动作通过 `save.commit()` 落盘即可完成。例如不产生公共变化的资源计时开始，无需为了统一 API 而额外读写平台。需要公共前置条件的动作另行要求同步水位，条件不足时返回明确状态。

### 7.2 涉及云端的动作

`operations.commit()` 接收 `expectedRevision`、存档变化及声明过的云端效果；宿主一次原子写入存档和 outbox，落盘后才确认已接收。

```text
durable -> queued -> sending -> verifying -> confirmed
                         \-> retry-wait -> sending
                         \-> blocked
                         \-> conflict
```

规则：

- 发布与删除使用同一账号级串行队列；多个游戏卡共享限流预算。
- 同机多个工具实例须有账号级单写者或互斥机制；跨电脑仅靠本地锁没有全局串行保证，须依赖平台顺序、幂等和冲突处理。
- 暂时错误指数退避并加抖动；尊重平台重试提示，不用持续短周期轮询补偿限流。
- 发送结果不确定时先回读，再决定补传，避免重复发布。
- 永久参数错误保留 `blocked` 项及依赖，不无限刷同一个错误；修正或明确取消后继续。
- 断电、崩溃、重启后只恢复已落盘待办，不重复扣金币或重新执行原始游戏动作。
- 严格 FIFO 下前项阻塞会阻塞后项；这是明确语义，不绕过失败项偷偷并行。
- 账号退出后保留原账号待办并停止执行；换账号不使用新账号的凭据续传旧任务。
- 云端数据缺页、缺片、版本冲突时返回不完整状态，不以本地存档冒充完整云端。

远端平台不提供的事务、比较并交换或严格一次执行保证，SDK 不进行虚假承诺。`queued` 不是“全服已同步”；竞态交易、领地冲突等玩法须定义冲突决议与必要的补偿。

### 7.3 删除是生命周期步骤

每种记录在 manifest 中声明 `append-only` 或 `replaceable`，以及实体键、版本字段、替代关系和引用规则。游戏自定义“为什么过时”，宿主校验“是否存在证明”；卡片声明本身不构成证明。

`records.retire()` 只接受宿主此前登记的自有记录句柄，并满足：

1. 替代结果已保存本地；涉及数据转移时，本地接收内容完整。
2. 同一局、同一动作的替代记录已从平台完整回读。
3. 当前读取水位完整，替代数据确实覆盖旧记录的全部效果，而非只覆盖其中一个字段。
4. 无保留历史、交付确认、待执行动作或其他可见记录仍依赖旧内容。
5. 待删除平台对象属于当前账号，删除不会级联破坏他人回复。

例如召回角色：先保存完整随身档案，确认公共位置移除/替代记录，再退役该账号旧部署档案。多实体记录只覆盖其中一个角色时，整条旧记录继续保留。

删除失败只留下原精确清单项，不扫描全区扩大目标；迁移指针与当前启动锚点由宿主管理，卡片的普通删除权限不覆盖它们。普通删除保留根锚点；只有宿主确认完整分支连续两次稳定、根与全部回复均属于当前账号且没有清单外内容时，生命周期清理才会先删回复、复查空分支、再删根并回读确认。平台缺少原子分支条件删除，复查与根删除之间的极窄竞态仍按保守失败和持久化重试处理。

## 8. 模型任务规范

每张卡可以定义自己的任务，宿主无需硬编码“将领生成”等名称。任务必须在当前已批准发布包中登记：

```json
{
  "taskId": "character.dialogue",
  "version": 1,
  "inputSchema": "schemas/dialogue-input-v1.json",
  "outputSchema": "schemas/dialogue-output-v1.json",
  "promptRef": "worldbook/dialogue-v1",
  "context": [
    "input",
    "save.character",
    "save.dialogueHistory"
  ],
  "maxInputBytes": 65536,
  "maxOutputBytes": 32768,
  "billing": {
    "confirmation": "host",
    "retryConfirmation": "each-attempt"
  }
}
```

任务 Schema 使用工具支持的有限 JSON Schema 子集；限制深度、条目数量、字符串和数字范围，拒绝外部 `$ref`、自定义执行代码及高成本验证表达式。上下文引用使用受限字段路径，不运行模板表达式或任意 JS。

调用示例：

```javascript
const result = await fyow.model.run({
  taskId: "character.dialogue",
  input: { characterId: "character-1", text: "你好" },
  idempotencyKey: "MODEL_OPERATION_UUID"
});
```

宿主根据已登记任务生成世界书触发标记、输入与提示词，不接收任意平台 URL、作品 ID、请求头或访问令牌。创作时可以编辑任务提示词，运行中仍只调用当前版本登记的任务。

统一要求：

- 提示词明确给出由输出 Schema 生成的 `json` 代码块范例；只解析单个 JSON 对象或单个 JSON 代码块，拒绝额外可执行内容。
- 输出结构由宿主确定性验证；验证失败不应用游戏结果。
- 模型返回“工具调用”“管理员命令”等文字时，视为普通数据。只有已登记、经过权限检查和必要确认的动作才会执行。
- 每次产生新计费请求的重试都再次经宿主确认；断线重连不自动重放可能已计费的请求。
- 计费任务有调用次数/并发上限及费用记录。平台若不支持请求前精确限价，预算只作停止后续调用的规则，不宣称单次扣费绝不会超出估计值。
- 任意新模型结果都不直接拼入宿主 HTML，也不执行为主进程代码。

创作助手生成的程序则进入草稿构建和沙箱预览流程，与运行时角色对话结果分开处理。

## 9. 创作助手流程

创作助手运行在工具的受信创作页，风月模型只得到创作材料和受限工具定义，模型自身不拥有平台账号权限。

工作流：

```text
需求描述
  -> 玩法与数据结构草案
  -> manifest / 程序 / 提示词 / 世界书
  -> 确定性校验
  -> 假数据沙箱预览
  -> 用户反馈与局部修订
  -> 展示发布差异及权限变化
  -> 用户确认
  -> 平台保存和双视角回读验证
  -> 导出游戏卡
```

助手的工具清单：

| 工具 | 效果 | 约束 |
| --- | --- | --- |
| `draft.read` | 读取当前草稿指定条目 | 不读取任意文件或其他项目 |
| `draft.patch` | 修改 manifest、程序或提示词 | 基于草稿 revision；结构化路径、检查旧版本 |
| `sdk.lookup` | 查询实际可用的 API、样例和限制 | 由工具提供固定文档，减少虚构接口 |
| `draft.validate` | 检查结构、引用、资源和权限 | 报告确定性错误，去掉本机路径和私有资料 |
| `preview.run` | 用虚构状态运行 | 默认无平台写入、无真实模型计费 |
| `preview.inspect` | 获取预览日志和界面状态 | 只读当前预览，不读取登录窗口或桌面 |
| `model.sample` | 测试一个任务的真实模型输出 | 独立确认积分和上下文内容 |
| `publish.prepare` | 生成待发布差异 | 不提交平台；返回摘要待工具界面确认 |

实际 `publish.commit` 不向模型开放为可自行完成的工具，由受信界面接收用户确认后执行。卡片内的 `ui.confirm()` 或模型文字“用户已同意”都不构成发布许可。

编辑器字段分为：

- 基础：标题、简介、卡片版本、运行接口版本。
- 程序：主要 HTML/CSS/JavaScript，包内资源。
- 数据：存档 Schema、公共记录类型、替代/删除规则。
- 模型：前置词、主提示词、后置词、任务输入/输出 Schema。
- 世界书：触发关键词、内容、启用状态、概率及触发范围。
- 运行许可：允许的 SDK 能力、模型调用规则、目标作品。

草稿每步持久化，支持撤销、恢复和版本差异。模型代码按条目提交，长程序分段生成并用条目摘要校验，避免整段 JSON 截断损坏已有草稿。修改使用结构化补丁与版本检查，不用模型直接生成任意 Shell 命令。

初版仅使用内联程序及包内资源，不安装模型指定的 npm 依赖。扩展库以工具维护、已审核的离线库目录提供；构建器本身不执行卡片提交的构建脚本。

## 10. 作品保存与更新

创作助手使用的模型作品与最终发布的游戏伴生作品是两个角色，须分别绑定；可以按需选择，不隐式覆写玩家正在使用的其他作品。新建作品或选择已有作品须由用户在创作页明确操作，编辑发布时主进程实时确认作者身份。

继续采用项目已经存在的作品配置适配器，而非模型直接操作平台登录页面：

- 详细介绍：承载程序发布包与版本清单。
- `pre_text`、`pre_prompt`、`post_text`：三段提示词。
- `world_book`：任务世界书条目。
- 保存后通过配置导出做别名归一化和逐字段回读。
- 另用普通玩家实际读取介绍的路径验证程序摘要与版本，不能只凭作者配置导出成功就宣布普通玩家已经读到新代码。

发布前验证程序、任务定义、提示词和数据 Schema 的组合版本。若平台不支持原子更新所有字段，就分阶段保存并标记待完成；全部回读一致后才宣布发布完成，失败时保留原发布记录与草稿用于恢复。

导入 JSON 中保存游戏身份、初始作品入口、作者身份和兼容要求。日常代码更新从当前有效伴生作品读取，不靠所有玩家重新下载 JSON；迁移沿已验证的原作者路由追踪，绝不以“找到名字相同的作品”代替路由。

第一版 `/2` 新卡使用在线优先：读取并验证当前发布包后运行；网络异常时明确等待或重试，不静默运行 JSON 内的旧备用代码。`/1` 卡保留现有兼容行为，备用代码移除属于单独迁移，不在本设计稿中改动。

权限扩大时在宿主重新确认，权限不变的普通程序更新沿原许可执行。平台身份认证和摘要匹配也不跳过第三方卡的运行隔离。

## 11. 隐私加固清单

应当先于开放任意自定义卡实施：

1. **统一账号投影。** 增加专门的 `CardIdentity` 构造器，只返回 `accountId` 和 `displayName`；积分由单独能力获取。已知邮箱或邮箱格式昵称用中性玩家别名替换，识别可用公开昵称后优先保留。
2. **移除邮箱回退。** 区分登录标识、邮箱和公开昵称，公开昵称缺失不再采用邮箱。检查 `accountName`、作者名称、角色设定默认名、模型输入与共享记录的同类回退。
3. **历史数据兼容。** 旧存档/记录中的邮箱式名称在投影和后续写出时清理，不篡改账号 ID、签名和记录摘要。既有平台历史中已公开的信息不因客户端投影修复自动消失，另行确认范围再清理自有记录。
4. **回包白名单。** 账号、作品、评论作者、模型结果、错误信息分别投影；不使用 `{...rawResponse}` 将平台数据整体交给卡片。
5. **隔离权限。** 桌面 preload 主框架限定，主进程验证 senderFrame；第三方卡专用进程/分区、最小卡片 API、设备权限默认拒绝。
6. **限制出口。** 卡片不自行发起外部请求、导航、下载或调用系统协议；公开评论、书信、模型请求均通过已绑定代理。
7. **日志与导出。** 诊断日志排除凭据、邮箱、请求头和原始账号响应；模型仅接收清理后的预览日志，卡包只导出当前草稿条目。
8. **确认不可伪造。** 登录、积分及发布确认在工具受信界面；卡片自报权限或自制弹窗不提升能力。

敏感字段检查和已知凭据字符串匹配可作为纵深防护，但不替代数据源隔离。即使模型受到提示词注入，也应只接触游戏数据和草稿工具；不能把“提示模型别泄露”当作隔离机制。

## 12. 验收矩阵

以下是后续实现的测试要求，不是本轮已经通过的测试。

| 场景 | 合格标准 |
| --- | --- |
| 有昵称、无昵称、邮箱作为用户名、昵称含邮箱 | 卡片保留账号 ID 和可用昵称；邮箱不进入账号投影与自动上下文 |
| 平台评论作者/作品作者资料带邮箱 | 返回的规范化游戏数据排除该字段，异常响应不原样回传 |
| 合成敏感值放入账号、日志、历史默认名称 | 状态、共享写入、模型输入、导出及错误出口均不泄露这些宿主提供的值 |
| 卡片尝试访问桌面 preload、父页面、其他分区 | 无桌面能力；主进程拒绝越界调用 |
| 伪造 sender/session/作者标记，退出后旧回包 | 无业务副作用，新会话不接受旧消息 |
| 各种外部加载、导航、新窗口、下载、设备请求 | 真实 Electron 测试中被拦截，而非只检查 CSP 字符串 |
| 卡片权限、任务或目标作品临时扩张 | 按当前批准版本执行；无新授权则拒绝 |
| 纯本地采集/练兵示例 | 存档原子保存，无多余平台调用 |
| 发布成功而回执丢失、进程中途退出 | 回读确认或续传，原动作和计费请求不被重复执行 |
| 召回/删除遇到缺片、替代记录不存在、引用残留 | 保留本地档案及旧云端记录 |
| 账号切换、同卡多实例、搬迁、重开一局 | 数据隔离，旧队列不被新账号或新一局执行 |
| 不同客户端同时写同一实体 | 按声明的版本和顺序处理冲突，不承诺平台不存在的原子事务 |
| 模型输出带代码、伪造管理指令、要求读取邮箱 | 作为不受信结果处理，不增加宿主权限 |
| 模型生成的无限循环、巨量 DOM、请求洪泛 | 有配额、无响应检测和由受信界面终止卡片的入口 |
| 创作中断、取消计费、取消发布 | 草稿保留，无后台自动发布或重复计费 |
| 普通玩家打开已更新作品 | 当前运行摘要与发布摘要一致，权限变化得到正确处理 |
| 两个玩法完全不同的新卡 | 使用同一宿主构建，未增加猎艳疆土式专用 IPC |

## 13. 实施顺序

1. 修复邮箱别名链路及回包投影，完成真实沙箱/IPC 隔离测试；暂不开放第三方任意卡。
2. 实现 `fyow-host/2`、通用存档/记录/模型代理和受信 SDK 文档，保留 `/1` 适配。
3. 用一张纯本地小游戏和一张多人共享数据小游戏验证泛用性，再接入真实平台。
4. 实现创作页、草稿工具、风月模型生成流程、虚构数据预览和逐次计费确认。
5. 完成作者发布、双视角回读和普通玩家在线更新测试，再开放自定义卡制作。
6. 猎艳疆土按模块迁移，避免为通用化重写现有同步、路由和将领保存链路。

本轮产物仅为此设计文档和账号投影的离线证据。版本号、运行代码、平台作品、安装包及快捷方式均未改动；安全修复、SDK 和创作页需要后续实现与验收。
