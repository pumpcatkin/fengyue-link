# 在线游戏编辑器通用设计与接口

核对日期：2026-09-28

本文记录风月联机工具中“在线游戏编辑器”的通用约定和当前实现边界。
本文依据 `游戏卡制作经验与接口手册.md`、现有源码和回归测试整理；其中标注为“设计约定”的内容不代表平台已经提供同名公共 API。

## 1. 目标

在线游戏编辑器位于工具主界面，面向游戏卡作者和维护者，提供：

1. 导入并校验 `fyow.game-card/1` 游戏卡。
2. 将游戏卡拆解为身份、程序、作品配置、提示词、世界书和 Agent 协作配置。
3. 在本地分区编辑后重新组包，重新计算配置摘要、程序摘要和整包摘要。
4. 作者保存时可以同步更新伴生作品，并通过平台导出接口回读确认。
5. 通过多个 Agent 协作生成玩法、提示词、界面和验证建议，并把进度持续同步到工具界面。

编辑器不把任意模型输出直接当作主进程代码执行。程序只作为受限单文件 HTML 进入游戏卡沙箱，宿主能力仍由受信主进程和明确的游戏适配器提供。

## 2. 文档事实与用户需求的区分

### 已存在的实现事实

- 当前卡格式是 `fyow.game-card/1`。
- 卡片中的伴生作品详细介绍包含 `FYOW-PROGRAM/1` 程序信封。
- 平台创作配置由全局前置词、主提示词、后置词和世界书等部分组成。
- 主进程已经提供卡片导入、导出、云端更新、沙箱运行和在线世界同步能力。
- 模型请求由宿主发起，游戏卡前端不能直接访问平台 HTTP、Token、Cookie、文件系统或 Electron IPC。
- 旧的《猎艳疆土》卡仍由现有专用适配器运行；新增编辑器不把其 `intent` 当作所有游戏的通用接口。

### 本次编辑器设计约定

- 编辑器工作区使用 `fyow.game-card-editor/1` 项目结构。
- 项目会保存 Agent 组件绑定和最近一次 Agent 草稿。
- Agent 组件默认分为世界架构师、结构化提示词师、运行时通信工程师、玩家体验设计师和卡包验证审查员，并由中枢合并审查。
- Agent 默认优先使用可识别的 GPT 5.6 及以上模型，其次是 Claude Opus 4.6 及以上，最后是 GLM 5.3 及以上；没有可用模型时沿用平台模型目录的可重试机制。
- 编辑器保存本地游戏卡不会自动发布伴生作品。
- “保存并同步作品”才会执行作者身份校验、云端写入和导出回读。

## 3. 卡包拆解模型

编辑器打开一张卡后，内部项目对象包含以下分区：

```json
{
  "schema": "fyow.game-card-editor/1",
  "card": {
    "cardId": "卡编号",
    "gameId": "游戏编号",
    "title": "游戏标题",
    "version": 1,
    "exportedAt": null,
    "companion": {
      "origin": "https://PLATFORM_ORIGIN",
      "workId": "WORK_ID",
      "authorAccountId": "AUTHOR_ACCOUNT_ID",
      "name": "作品名称",
      "summary": "作品简介",
      "language": "zh-Hans"
    }
  },
  "program": {
    "format": "fyow.program/1",
    "apiVersion": 1,
    "digest": "程序摘要",
    "html": "<!doctype html>..."
  },
  "configuration": {
    "app": {},
    "pre_text": "",
    "pre_prompt": "",
    "post_text": "",
    "world_book": []
  },
  "agents": [],
  "validation": {
    "configurationSha256": "配置摘要",
    "packageSha256": "整包摘要",
    "programDigest": "程序摘要"
  }
}
```

`configuration` 保留导入卡中的其他字段。编辑器的结构化分区覆盖名称、简介、三段提示词、世界书和程序；高级配置分区用于查看和修改完整 JSON 快照。

## 4. 保存与发布

### 本地保存

本地保存流程：

1. 读取编辑器分区。
2. 解析世界书 JSON。
3. 重新打包单文件 HTML 程序。
4. 生成新的 `FYOW-PROGRAM/1` 信封。
5. 重新计算配置摘要和整包摘要。
6. 写入本地游戏卡库及导入目录中的来源文件。
7. 保存后回读本地库，确认卡仍可通过 `validateGameCard()`。

本地保存不会写平台作品。

### 保存并同步作品

作者同步流程：

1. 检查当前账号与卡片绑定的 `authorAccountId` 一致。
2. 使用平台创作配置保存接口写入全部配置字段。
3. 使用导出接口回读配置。
4. 比较详细介绍、全局提示词、后置词和世界书。
5. 依据回读结果创建新的本地卡快照。
6. 将本地库和导入目录中的同一 `cardId::workId` 来源更新。

同步失败时保留本地编辑项目，不把失败误报为发布成功。

### 创建新伴生作品

创建作品属于独立操作。编辑器可以在作者明确选择“创建并同步”时：

1. 创建新作品。
2. 将当前程序和完整配置导入新作品。
3. 回读新作品配置。
4. 重新绑定卡片中的 `workId` 和作者账号。
5. 将新卡保存为新的本地库键。

创建新作品不会删除旧作品，也不会自动搬迁旧服务器账本。

## 5. 游客、玩家和服主边界

### 玩家打开游戏

普通玩家打开游戏时：

- 宿主读取伴生作品详细介绍中的有效程序。
- 如果云端程序比本地快照新，宿主将验证后的程序更新到本地游戏卡库和导入目录来源。
- 更新只针对当前 `cardId::workId`，不会覆盖其他服务器卡。
- 更新只保存程序快照及其摘要，不把玩家的私有状态写入卡包。

### 服主打开游戏

服主打开游戏时：

- 允许读取云端最新程序运行。
- 不因为打开游戏而自动改写服主本地 JSON。
- 服主需要在编辑器中点击“保存本地游戏卡”或“保存并同步作品”，才产生明确的作者写入动作。
- 云端作品写入仍要求作者身份和平台回读校验。

这样可以避免服主打开服务器时，本地卡在没有明确编辑动作的情况下被自动覆盖。

## 6. Agent 协作模式

### 默认组件

| 组件 | 职责 | 建议输出 |
| --- | --- | --- |
| 世界架构师 | 玩法目标、状态、事件和任务边界 | 状态 Schema、事件 Schema、任务清单与不变量 |
| 结构化提示词师 | 三段提示词和世界书 | 前置词、主提示词、后置词、世界书条目 |
| 运行时通信工程师 | 宿主消息、请求节奏、去重、断线恢复 | 消息计划、限流约束与重连建议 |
| 玩家体验设计师 | 单文件前端布局和交互 | 页面结构、组件清单、玩家反馈 |
| 卡包验证审查员 | 兼容性、权限、体积和回退检查 | 问题列表、严重等级、修复建议 |

当前组件使用游戏卡的伴生作品请求平台模型，角色提示词与共享知识库由宿主注入。界面不开放组件作品编号编辑。不同组件独立提示词作品的自动创建与维护尚未实现。

### 协作流程

```text
编辑目标
  -> 世界架构师
  -> 结构化提示词师
  -> 运行时通信工程师
  -> 玩家体验设计师
  -> 卡包验证审查员
  -> 中枢审查与配置补丁
  -> 本地 Agent 草稿
  -> 人工审阅
  -> 本地组包
  -> 可选云端同步
```

当前实现采用串行编排，原因是后一个组件需要看到前一个组件的职责和当前项目快照。后续可以扩展为架构师与界面设计师并行，再由验证审查员汇总。

所有组件结果通过 `agentOutputs` 返回中枢。JSON 解析位于自动模型重试回调内部，空输出、数组、非 JSON 与缺少中枢审查结论会进入模型降级。中枢必须返回 `configurationPatch` 和布尔值 `validation.approved`；拒绝时保留草稿但不应用补丁。空提示词和空世界书不会由 Agent 自动覆盖现有内容，作者仍可手动清空字段。

共享知识库来自仓库内《猎艳疆土》的实现：`fyow-host/1`、UUID `requestId`、意图幂等键、1000ms 本地视觉时钟、5000ms 宿主记录轮询、失败退避和平台限流。卡片端不额外建立轮询链路；新消息类型仍须宿主登记。

### 模型选择

编辑器 Agent 使用当前平台模型目录，并按下列优先级排序：

1. GPT 5.6 及以上。
2. Claude Opus 4.6 及以上。
3. GLM 5.3 及以上。
4. 其他可用模型作为最终回退。

同一组件失败后会重新读取模型目录并尝试下一个候选模型。积分不足、登录失效和明确权限错误不会被无限重试。网络、临时服务错误和结构化输出错误可以进入回退流程。

### 进度同步

主进程状态中使用 `onlineWorldEditor` 字段同步：

- Agent 编排任务 ID。
- 总体状态：`running`、`completed`、`failed`、`cancelled`。
- 当前组件。
- 每个组件的等待、运行、完成、失败状态。
- 实际使用模型和错误消息。
- 最终 Agent 草稿。

编辑器页面通过现有 `backend:state` 事件实时刷新，因此用户可以在模型请求期间看到当前组件和实际模型。

## 7. 宿主和卡片边界

编辑器生成的程序可以使用：

- 单文件 HTML、内联 CSS、内联 JavaScript。
- 受宿主协议声明的 `postMessage` 请求。
- 受限的状态、公共记录、定向消息和模型任务能力。

编辑器生成的程序不可以直接使用：

- 平台 Token、Cookie、登录凭据或邮箱。
- 任意平台 HTTP 接口。
- 任意本地文件和目录。
- Electron IPC。
- 未声明的游戏行动类型。
- 其他作品、账号或赛季的数据。

新游戏若需要新的宿主能力，必须同时增加：

1. 请求和响应 Schema。
2. 权限和作用域。
3. 体积、频率和积分限制。
4. 幂等键和重试规则。
5. 离线、重连和错误码语义。
6. 主进程路由和自动化测试。

## 8. 发布验收

编辑器项目完成后，至少执行：

1. `validateGameCard()` 离线校验。
2. 程序单文件、CSP、外链资源和体积检查。
3. Agent 草稿结构检查。
4. 游客打开游戏并验证本地程序快照更新。
5. 服主打开游戏并验证本地 JSON 不自动变化。
6. 作者本地保存并重启读取。
7. 作者云端同步并导出回读。
8. 非作者尝试发布并确认被拒绝。
9. 模型失败后确认回退和进度状态。
10. `npm test`、`npm run build` 和沙箱验证。

修改作品配置但不改变宿主接口时，可以通过伴生作品传播；修改主进程、IPC、规则引擎或沙箱边界时，仍然需要发布新客户端。

## 9. 2026-09-28 测试版修复

- 返回按钮位于宿主页面右上角 24×24 像素范围，绝对定位，不挤占卡片布局；悬停或键盘聚焦时显示。关闭后卸载 iframe 并返回游戏库。
- 新建与导入集中在“选择本地项目”弹窗；编辑器顶部仅保留保存、同步与返回。
- 编辑保存优先读取规范字段，避免旧 `prpt/pretxt/posttxt/desc` 别名覆盖已编辑提示词与程序。显式空字符串仍代表作者主动清空。
- 云端保存显式设置目标 `app.id`；保留额外字段时同步已存在的别名。回读最多三次，对换行和世界书服务端元数据做归一化，真实内容不一致仍报错并标出字段。
- 旧版默认起始页缺少宿主握手。仅精确匹配旧模板及其 CSP 注入版本时迁移；自定义 HTML 保留原样。新起始页使用 UUID 请求编号、单请求等待和 120 秒超时恢复。
- 起始页接入宿主不等于已实现完整新玩法。当前 Agent 自动应用范围仍是配置与提示词，不生成或执行主进程代码；独立玩法程序及新的宿主能力仍需具体实现。

离线验收使用 `tests/online-game-editor.test.ts` 模拟真实主进程编排，验证前序输出、中枢汇总、模型降级与审查拒绝。`scripts/verify-game-card-render.cjs --starter` 在真实 Electron 沙箱测试握手、同步回执、独立返回和保存后提示词，覆盖桌面与窄窗口。测试不登录平台、不消耗模型积分、不写用户作品；线上模型质量与云端账号实测需单独记录。
